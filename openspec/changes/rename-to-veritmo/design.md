# Design: rename-to-veritmo

## Context

The old name lives in six kinds of place, each with a different cost: the Go module path (531 files, mechanical); the binary name (scripts, Dockerfile, workflow, docs, 22 specs); user directories on the machines where the server runs (data loss if not migrated); environment variables in `compose.yaml`, the owner's deploys and the tests; Docker image and container names (rebuild on the server); Prometheus metric families (Grafana dashboards break silently). The repositories are a seventh, in the owner's hands.

## Decisions

### One commit for the mechanical part, one for the migration, one for docs and measure

The module path, imports, binary, images, metrics and texts change together in the first commit: a half-renamed tree does not build, so there is no sensible intermediate state. The configuration migration and the environment aliases are a second commit because they add behaviour and tests. Docs and the Grafana JSON are a third. `go build ./... && go test ./...` passes after each.

### Module path and binary

`go.mod` says `module veritmo`; every `"mediaOrquestator/` import becomes `"veritmo/` (`sed` over `*.go`, then `gofmt -l` must print nothing). `cmd/orchestrator/` moves to `cmd/veritmo/` with `git mv` so history follows. The binary is `veritmo`; `veritmo-api` stays as a symlink in the Docker image and `bin/` for the scripts that look for `*-api serve` in `/proc/*/cmdline` (`scripts/serve.sh` updates its regex to `veritmo(-api)? serve`).

### Directories migrate once, by rename

`settings.ConfigDir()` (today `~/.config/mediaorquestator`, honouring `XDG_CONFIG_HOME`) becomes `~/.config/veritmo`. On the first call in a process, when the new directory does not exist and the old one does, the old one is renamed to the new (`os.Rename`, same filesystem) and one line is logged: `moved ~/.config/mediaorquestator to ~/.config/veritmo`. When both exist, the new one is used and a warning says the old one is ignored and may be deleted. Nothing is copied, nothing is deleted. The same for `~/.cache`. `scripts/serve.sh` and `scripts/install.sh` read the new paths and, before reading, apply the same rename when only the old directory exists, so a server started by the script before the binary runs still finds its token. The pid files `serve-<port>.pid` travel with the directory.

### Environment variables: new names, old names honoured for one release

Every `MO_X` becomes `VERITMO_X`. The settings package reads `VERITMO_X` first and falls back to `MO_X`; when a fallback is used it logs once per variable: `MO_DB_HOST is obsolete, use VERITMO_DB_HOST`. The compose files, the workflow and the docs use the new names only. The fallback is removed in a later change once the owner's deploys are updated; a `TODO(veritmo-env)` marks the spot.

### Docker and containers

Images `veritmo/server`, `veritmo/tools`, `veritmo/heartmula`, `veritmo/diffrhythm2`, `veritmo/ctxpress`; compose project `veritmo`; music containers `vt-<engine>`. The server's container runner and `scripts/music-containers.sh` change together (the existing test that compares them keeps them honest). The owner rebuilds the images on the server (`docker compose build`) and removes the old `mo-*` containers if any are left; the task says how.

### Metrics

Families `veritmo_*`. No dual export: the owner is the only consumer and `docs/grafana/*.json` is regenerated by `docs/grafana/build_dashboard.py` (it is a Python script already in the repo; the task runs it, it does not write Python). Files renamed `veritmo-dashboard.json` and `veritmo-machine.json`.

### Specs: ten modified here, the command name by a textual pass

The requirements that state a directory, a variable, an image or a metric family are modified in this change's deltas with their full text. The word `orchestrator` as the command name appears in 22 spec files (`orchestrator data`, `orchestrator serve`, …) and the container prefix `mo-` in one; changing them is spelling, not behaviour, so the archive step of this change runs `sed` over `openspec/specs/**/spec.md` (`\`orchestrator ` → `\`veritmo `, `orchestrator-api` → `veritmo-api`, `mo-<engine>` → `vt-<engine>`) and a grep proves no old name remains. Writing 22 MODIFIED deltas that differ by one word would bury the real changes.

### Repositories

Gitea and GitHub both redirect a renamed repository (clones, fetches and web links keep working), so the order is: merge this change, rename the repositories, then `git remote set-url` on the Mac, the server and the worktree of the public edition. `scripts/sync-public.sh` defaults `PUBLIC_DIR` to `../veritmo-public`; the owner renames the folder. The GitHub `About` text and the Gitea description get the one-line tagline so the name is indexed with its meaning: *"Veritmo — ver el ritmo. A Go server that turns a song into typographic motion graphics."*

### The dashboards

`dashboards-labs` keeps its name (it is a workspace of dashboards, the name describes it). Its change `rename-server-veritmo` renames the server in texts (es/en), `README`, `ESTADO`, `contract/SOURCE.json`, `scripts/public-scope.mjs`, the PWA manifest (`name`, `short_name`) and the Tauri identifier `com.jesussuero.veritmo` (a new identifier means the desktop app's local data starts empty; the dashboard keeps nothing there worth migrating), then `contract:sync` after the server's `openapi.yaml` title changes.

## Risks

- A deploy that still sets `MO_*` keeps working with a warning; one that reads the token from `~/.config/mediaorquestator/token` by hand (a cron, a script outside the repo) breaks. The migration log line names the new path.
- Grafana loses history continuity on the renamed series. Accepted; the dashboards are the owner's.

## Verification

`go vet ./... && go test ./...`; `grep -rIl -i "mediaorquestator\|MO_[A-Z]" --exclude-dir=.git --exclude-dir=.orchestrator --exclude-dir=third_party --exclude-dir=node_modules .` prints only the deprecation-fallback code and the migration code; `docker compose config` resolves; the server starts on a machine with the old `~/.config/mediaorquestator` and answers with the same token; `curl /api/metrics` shows `veritmo_info`; `scripts/check-docs.sh` passes.
